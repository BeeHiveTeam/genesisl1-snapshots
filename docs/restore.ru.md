# Восстановление отдельной ноды GenesisL1

Нужен Linux с Bash, Python 3.11+, `curl`, `jq`, `flock`, `sha256sum`, `tar` и `lz4`. Укажите пустой каталог на NVMe. Для архива, восстановленной базы и уплотнения таблиц ориентируйтесь на запас до 1 ТБ. Первый архив BeeHive занимал при скачивании 51,09 ГБ. Автоматическая установка бинарника поддерживает Linux amd64.

## Выбор каталогов

Оператор выбирает, какую ноду проверить и на какой диск восстанавливать. Если пропустить параметр пути, скрипт использует указанный в таблице каталог относительно домашней директории пользователя, запустившего команду. Режим `--source auto` выбирает источник снимка.

| Параметр | Для чего нужен | По умолчанию |
| --- | --- | --- |
| `--inspect-home` | Каталог существующей ноды. Скрипт читает её конфигурацию и проверяет локальный RPC. На новом сервере параметр можно пропустить. | `~/.genesis` |
| `--target` | Отдельный рабочий каталог для архива и восстановления. Новая нода создаётся в подкаталоге `node/`, её база — в `node/data/`. | `~/.beehive-genesisl1` |

Если нода установлена в нестандартный каталог, укажите её путь явно. Например, при действующей ноде в `/srv/genesis/mainnet` и цели `/mnt/data/l1-receiver` восстановленная нода будет в **`/mnt/data/l1-receiver/node`**. Родительский каталог `/mnt/data` должен существовать и быть доступен для записи. Для первого запуска выберите новый или пустой каталог. Скрипт отклонит `--target`, совпадающий с каталогом существующей ноды или расположенный внутри него.

Из корня репозитория проверьте сумму скрипта, получите список источников и посмотрите план без скачивания архива. Подставьте свои пути в обе команды восстановления.

```bash
(cd restore && sha256sum -c beehive-sync.sh.sha256)
bash restore/beehive-sync.sh --list
bash restore/beehive-sync.sh --plan --source beehive-native \
  --inspect-home /srv/genesis/mainnet --target /mnt/data/l1-receiver
```

Когда в плане появятся нужные сеть, высота, архив и каталог, запустите восстановление в `tmux`.

```bash
bash restore/beehive-sync.sh --source beehive-native \
  --inspect-home /srv/genesis/mainnet --target /mnt/data/l1-receiver --yes
```

После обрыва повторите ту же команду с тем же `--target`. Скрипт использует отдельную ноду со своими ключами и портами. Проверьте сверку с независимыми RPC и догон текущей высоты mainnet. При создании нового плана до конца доверия контрольной точки должно оставаться больше часа. Другие источники и интерактивный выбор `auto` описаны в `bash restore/beehive-sync.sh --help`. [Актуальный манифест Native](https://l1-snapshots.bee-hive.work:8545/native/latest.json)

При восстановлении скрипт сверяет контрольную точку и итоговый блок с CometBFT RPC `https://26657.genesisl1.org` и `https://rpc.genesisl1.firsttensor.com`. При публикации первый свидетель тот же, второй предоставляет anode.team.

При каждом запуске восстановленной ноды скрипт удаляет прежний файл `verified-height` из целевого каталога. Когда нода сообщает, что догнала сеть на высоте H, и оба свидетеля подтверждают блок H−1, скрипт записывает H в этот файл. Нода продолжает работать. Если нода штатно завершилась до успешной сверки, скрипт возвращает код 1. Посмотрите `node.log` в том же каталоге и повторите команду для продолжения.

Скачанный Bash-скрипт уже содержит Python-модуль и работает одним файлом. Для изменений редактируйте `restore/client.sh.in` или `restore/helper.py`, затем выполните `python3 restore/build_client.py`. Команда пересобирает скрипт и его SHA-256. CI сверяет оба файла с исходниками.
